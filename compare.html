How rules are matched
Identical
The rule text is the same (ignoring spaces), or both sides are the same “Undefined” / “Too many source nodes” marker.
Equivalent
Same logic, written differently: reordered terms, De Morgan forms like !(A || B), or redundant terms. Proven by normalising both rules, or by checking every input combination (up to 12 regulators).
Different
The two rules give different outputs for some input. The row shows the regulators that were added, removed or flipped, the share of inputs on which they agree, and example inputs where they diverge.
Unverified
More than 12 regulators and no difference turned up in 2,048 sampled inputs, but it can't be proven. It is not counted as a match.
Rule lost
The original has a real rule; the refactored file has Undefined or Too many source nodes.
Rule gained
The reverse: the original had no rule, the refactored file does.
Marker changed
Both sides have no rule, but a different marker (Undefined vs Too many source nodes).
Only in original Only in refactored
The target appears in just one file.
Missing nodes
A node is any gene named in a file, as a target or as a regulator. If a rule differs because it uses a gene that is not a node in the other file, the refactored pipeline could not have used it. A mismatch counts as fully explained when the two rules agree once those absent genes are held at a constant state (0 or 1). For a lost or gained rule, when every regulator is absent. For a target in one file only, when that gene is not a node in the other file at all.
Partly missing nodes
Absent genes are involved, but the rules still differ after accounting for them (or there are too many regulators to check, over 12).
Not node-related
Every regulator exists in both networks, so the difference is a genuine change in the rule or in whether a rule was learned.
